# 平台后台完善方案

2026-10-28，合并 Codex 页面实测与 Claude 的产品评估。保持现有绿色、暖白色视觉及三语，平台负责监督与争议处理，店铺负责履约和技师安排。

## 本轮实施

1. **工作台**：SOS 和具体高风险事项置顶；队列不再相加为误导性总数；零待办折叠；入口携带筛选。经营概况可选今日／本周／本月，明确预约金额与实际服务费口径。
2. **统一后台**：去掉顾客站头尾，工作台、客服、评价和消息复核使用一致的后台导航及语言切换；页面标题本地化。
3. **订单**：主动打开详情侧栏，支持关闭、Escape 和焦点恢复；明确上门／到店、下单时间、筛选和日期区间；默认展开关联时间线；保留安全和财务关联。
4. **顾客查询**：按姓名、邮箱、预约编号搜索，结果分页；详情关联订单、本人权限可见的工单和限制状态。仅客服等具备工单权限的岗位可查询，读取留审计，不返回密码、验证码、详细地址或其他岗位不可见的私密工单。限制操作从明确的顾客身份发起，沿用原因、时限、版本和审计规则。
5. **审核及名册**：资质、门店、照片视频、主页内容、名册、质量及停用善后分区切换；保留已有危险操作确认和原因表单；支付路由使用中性名称并明确完成状态。
6. **安全**：保留原有 OPEN／RESOLVED 兼容状态，增加管理员接手、跟进期限、联系记录和交接；按版本防止并发覆盖，内部记录不对顾客、技师和商户公开。
7. **审计和通知**：常见动作使用三语说明，操作人不再根据编号猜成顾客；通知面板明确账号邮件与业务通知的启用范围。

## 合并评估时的取舍

- 工单分派、二次确认、年费续费和财务报表已经存在，继续复用。演示账号入口仅作为演示能力，不能当作正式账号权限缺陷。
- 平台兜底先通过安全接手、预警跟进和既有平台裁决闭环处理。直接取消及代店铺退款需要单独定义授权、资金执行、失败重试与通知规则；支付按用户要求暂缓，不增加绕过原交易规则的按钮。
- 可编辑地区／费率／年费需要版本生效时间、旧订单快照保护、双人复核和回滚，列为下一阶段。不能把可编辑输入框当成配置中心已经完成。
- 平台优惠券、付费推荐位和内容管理按后续运营需求另行实施。

## 验证

覆盖顾客查询权限与隐私、工单队列筛选、安全接手和交接的并发与权限、订单上门／到店筛选、统计日期边界、审计角色。执行 API／前端业务测试、类型检查、构建；隔离环境核验三语 PC／手机页面和侧栏键盘操作。主预览数据保持不变。

## 本轮完成及检查结果

- 上述七项已实施。名册新增只读档案侧栏，可关联该店订单、技师、履约质量和年费方案；更完整的技师质量趋势、经营配置审批及营销能力仍按后续阶段推进。
- 顾客搜索每页 20 条，要求明确条件；按顾客归并订单，避免为每个顾客反复扫描全部预约。顾客详情按其标识查询关联预约。
- 安全事件界面展示最近 50 条内部处理记录；每次接手、联系及交接另存历史记录并关联审计，避免界面的展示上限造成历史丢失。
- 771 项 API 测试、147 项前端业务测试全部通过；后台隔离 HTTP 回归 93 项通过。新增覆盖权限、私密工单、限制并发、安全交接、服务方式、JST 日期及统计口径。
- 三语 × 12 个后台页面 × PC／手机宽度共 72 组，另补 320px 窄屏 9 组，共 81 组页面检查，无整页横向溢出。浏览器验证了顾客查询、工单直达、门店审核直达、安全接手留痕、店铺订单筛选、订单侧栏及 Escape 后焦点恢复。
- 修正三个旧测试的预约时间夹具：用次日 JST 中午替代随运行时刻变化的晚间预约，不修改营业时间规则。
- 最终类型检查、生产构建和差异检查通过；主预览网页与 API 均正常响应。
- 支付、直接代店铺退款及可编辑费率配置未纳入本轮；继续保留现有报价快照、退款执行与平台裁决边界。
