## 已实现

1. **内部处理安排**：客服详情中独立展示业务组、负责人、阶段、跟进时间和内部履历。支持客户支持、商家运营、信任与安全三个组；分派是本地运营元数据，不向真实员工或外部渠道发送消息。
2. **认领和释放**：仅能由当前管理员认领，不接收任意负责人 ID。已有其他负责人时必须先明确释放。未认领只能停留在待分派；释放或转组交接回到待分派。当前演示身份为一个管理员，正式员工目录与成员分权仍需生产集成。
3. **下一步状态**：待分派、处理中、等待提交人补充、等待店铺回复、等待内部核查；工单结案后只读。私密报告不能设置为等待店铺，业务组变化不改变共享范围。
4. **时间约束**：必须选择未来七天内的跟进时间，输入明确使用日本时间，不随浏览器时区变化。内部时间不改写原工单期限。队列分别显示回复超时与跟进到期，到期工作优先、结束记录后置。
5. **自动恢复处理**：等待的一方发送新消息后，内部状态恢复为处理中，跟进时间设为当前时间；店铺超时升级也返回待办。结案同步结束内部工作；提交人申请重开时恢复负责人，有负责人回到处理中，无负责人回到待分派。
6. **可追溯交接**：每次人工安排须写 10–3000 字内部备注；履历追加保存，保留当时业务组、阶段、负责人和跟进时间。自动回复恢复、升级、结案、重开也记录履历。
7. **后台队列**：安全治理中增加业务组筛选及全部、待认领、我负责的、跟进到期、回复超时入口；与已有店铺、搜索、状态条件组合，数量跟随业务组筛选。工单独立加载更多，安全事件保持自己的分页。

## 隐私、并发与兼容

- 内部处理与备注使用独立记录，不附加到提交人可读的 `SupportTicket` 或 `TicketMessage`；只有 ADMIN 可访问处理接口，其他角色返回 403。
- 普通工单详情、所有角色的工单列表、后台摘要、共享审计和通知队列均不包含内部备注正文。后台摘要只增加无正文的处理元数据。
- 人工更新同时检查原工单版本 `ticketVersion` 与内部版本 `version`，避免覆盖新回复或其他管理员的处理。重试旧版本返回 409，不重复追加备注。
- 并发失败后刷新最新记录，保留内部备注与对外回复草稿供再次核对。变更安排不会退款、修改订单、解除账号限制或发送对外回复。
- 未建立内部记录的旧工单按分类生成默认业务组、空负责人和版本 0，读取不写入新记录；无需重置现有 SQLite。

## 实现与接口

- `hogulink-api/src/ticket-handling.ts`：管理员处理服务、默认队列归属、原子履历和状态同步。
- `care.ts`：在消息、结案、重开和超时升级的原事务中同步内部状态。
- `admin.ts`：管理快照增加 `caseHandling`，无备注正文。
- `ticket-handling-panel.tsx`、`admin-case-queue.tsx`：独立内部处理面板和队列；`handling-i18n.ts`、`admin-model.ts`：三语、日本时间与过滤排序。
- `GET /v1/admin/support-tickets/{id}/handling`：返回 `handling`、倒序 `history`。
- `PUT /v1/admin/support-tickets/{id}/handling`：`ticketVersion`、`version`、`team`、`state`、`ownership=KEEP|CLAIM|RELEASE`、`followUpAt`、`note`；严格拒绝未知字段。

## 本轮验证

- 全量 **125 项测试**：104 后端、21 前端业务规则；本轮新增 11 项后端与 3 项前端测试。类型检查及生产构建通过。
- 独立内存 API **452 项 HTTP/SSR 检查**：72 预约 + 90 售后 + 53 店铺 + 74 技师 + 93 后台 + 70 工单处理。新增检查复用测试预约，处理后结案，不新增 hold、不修改订单或支付。
- 三语言 × 320/390/768/1440 宽度 × 队列/详情，**24 组**页面；顾客/店铺/技师 × 三语言，**9 组**移动端回归。共 33 组正常响应，无脚本异常或页面横向溢出，手机表单使用 16px 输入字体。
- 浏览器实际完成认领保存、队列筛选、客户补充后恢复、私密备注隔离、转组释放；双窗口并发失败后保留两类草稿并成功再次保存。
- 测试写入仅使用独立内存 API，未修改主 SQLite 的工单、订单、审核或支付。页面截图位于 `.playwright-mcp/handling-*`。
