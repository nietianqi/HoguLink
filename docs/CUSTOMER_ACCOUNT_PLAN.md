# 用户个人中心：业务与布局完善方案

日期：2026-10-28。结合 Codex 与 Claude 对现有个人中心的评审实施，保留绿色、白色卡片与浅灰背景，只调整个人中心及相关预约入口。支付、优惠券、储值不在本轮实现范围内。

## 用户任务与信息顺序

个人中心优先解决三件事：确认预约进度、处理需要本人决定的事项、找到地址和售后。

手机布局：身份与设置 → 当前预约/待处理 → 继续填写预约（存在有效保留时）→ 我的预约 → 常用功能 → 最近预约/再约一次 → 条款与合作入口。地址与售后放在历史记录之前，避免用户为管理地址先滚过多张旧订单；手机最多展示两条最近预约，其他记录从“查看全部”进入。

电脑布局：保留账户侧栏，正文放身份、当前待办、预约分类和最近预约；移除重复的快捷条、常用服务列表。退出登录统一放在设置。

未登录只保留一个主要登录按钮；预约区说明登录后可查看进度，不重复堆叠登录横幅。已登录优先展示账号姓名，缺少姓名时使用通用称呼，不暴露内部账号编号。

## 业务口径

- 隐藏尚未开放的优惠券和储值卡片及设置入口，已有说明页面保留供旧链接访问。
- 移除常驻的“待提交预约”分类。继续预约仅对应未提交、未过期的保留记录，不代表正式订单或待付款订单；明确显示截止时间，到期自动撤下并重新获取数据。
- 分类为进行中、待评价、已完成、取消/关闭。已完成含待评价订单，分类数量不能相加作为订单总数。取消/关闭包含取消、拒绝、过期，不计入已完成。
- 待评价统一进入 `account/bookings?status=review`。由后端返回当前顾客全部可评价订单编号；已提交审核、已发布等记录不计入，拒绝和撤回的评价按既有规则重新纳入。元数据加载失败显示重试，不退回全部已完成订单。
- 当前预约继续沿用后端优先级：待同意改派 → 待确认完成 → 履约中 → 最近的其他进行中预约。按钮进入详情后再作决定，不在主页直接同意改派或验收。
- 订单卡展示技师姓名/可展示照片、店名、项目与时长、上门/到店、服务区域、JST 时间、金额和下一步。首页摘要不返回或展示顾客门牌、酒店房号、电话。详细地点和路线留在订单详情。
- 今天/明天以日本时区计算；开始时间提示使用服务端时间并随页面停留更新。进入服务中、待验收或待改派时，不继续显示普通开始倒计时。
- 最近预约去掉与当前预约重复的记录。已完成订单提供“再约一次”，复用既有后端接口核对店铺、技师、项目和服务方式，再进入新预约；不沿用旧时段、旧价格或个人住址。不可再约时提供选择其他服务的入口。
- 常用地址直接放在手机主页，收藏、浏览记录、消息、帮助与售后、预约指南同层展示；消息使用真实未读角标。服务地区不再作为伪设置入口。
- 技师照片只在肖像授权、身份和发布状态等条件满足时展示，授权撤回后回退通用图标。

## 一致性与边界

所有新文案覆盖日文、英文、简体中文；两端使用相同状态含义与列表筛选。保留自动前台刷新；正常状态不要求用户手动刷新，失败时提供清晰重试入口。手机点击区域保留足够尺寸，英文长文案允许换行，预约分类横向溢出时可滚动。

本轮不新增年费权益、支付方式、优惠券、余额或付费曝光；不修改主预览订单或账号数据。自动化测试使用内存数据库，浏览器验证使用独立的网页/API 与测试账号。

## 验证要点

1. 游客只有一个主要登录按钮，回跳到原个人中心。
2. 多笔待评价进入完整待评价列表，已提交审核的记录不混入；零条和加载失败有区别。
3. 当前预约正确区分上门/到店，展示对应区域，改派与完成确认维持原有权限流程。
4. 有效草稿出现继续预约，到期消失，不变成已提交订单。
5. 当前预约不在最近预约中重复出现，再约保留服务方式但重新选时间。
6. 三语在手机窄屏及电脑宽屏均可读，常用地址与设置可进入。
7. 接口只返回当前顾客的数据，主页不新增住址或联系方式，照片授权撤回有效。
