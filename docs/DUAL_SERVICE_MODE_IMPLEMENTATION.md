# 上门与到店服务首版实现

日期：2026-10-26。需求方案：[合并业务方案](DUAL_SERVICE_MODE_PLAN.md)。

后续更新：[顾客主动选择上门／到店](SERVICE_MODE_CUSTOMER_CHOICE.md)。浏览入口已移除顶部重复切换，改为卡片说明能力与价格、预约区主动选择；该说明优先于下文早期界面描述。

本轮在原有界面和四端业务上增加指定时间到店预约，不接真实支付，不自动为现有店铺编造实体门店，不提交或推送。原先 Claude 的未提交修改已保留，修改前副本在本地 `.qa/dual-service-baseline-20261026/`。

## 1. 已实现的业务

| 环节       | 行为                                                                                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 服务方式   | 独立 `fulfillmentMode=HOME_VISIT/IN_STORE`；旧数据未设置时为上门。现有即时/指定时间、指名/店铺安排维度保留                                                                   |
| 店铺能力   | 审核后的门店可开放到店；可关闭新的上门预约成为仅到店店铺，不取消旧订单                                                                                                       |
| 门店资料   | 独立接待地址、地区、坐标、联系电话、交通说明、照片（只能上传到平台，不接受外部链接）、营业时间、每周休息日、临时休息日期、床位/独占房间、清场时间                            |
| 审核       | 首次提交待平台审核，通过后才公开。之后修改地址、电话、交通说明、照片进入待审草稿，审核期间按已通过资料继续接单；营业时间、休息日、价格、接待单元立即生效。原订单地点快照保留 |
| 项目和人员 | 已审核放松项目可创建独立到店价目，价格/优惠/启停与上门分开，交通费固定 0；店铺配置技师服务方式，本人仍需确认任务                                                             |
| 费用政策   | 到店独立指名费、两套既有取消模板、最多两段独立时段附加费；原单冻结价格和政策                                                                                                 |
| 可约       | 必须完整落在到店营业窗口内，支持跨午夜、24 小时、休息日；可约列表、报价和开始检查保持一致                                                                                    |
| 资源       | 同时保留技师与接待单元。复用已有排他区间，资源使用独立名称空间；并发只有一笔能占用同一单元                                                                                   |
| 混排       | 同一自然人的所有方式共用日程；不同门店到店之间至少留 30 分钟保守转换时间，结合已有上门缓冲。未使用实时地图路程                                                               |
| 到店下单   | 填联系人和电话，无住宅/酒店地址；订单冻结接待地点；不套用酒店限制和首次深夜住宅条件，基础登录和资格门禁保留                                                                  |
| 受理与改派 | 到店首版走人工受理，SOLO 保留既有一键路径；店铺安排仍锁定合格候选，改派继续核对资格、时段和顾客同意                                                                          |
| 核销       | 顾客独有核销码，仅本店可核销；服务端检查订单状态、版本、凭证及时间。签到不等于开始或验收                                                                                     |
| 履约       | 到店不允许出发/到达事件；核销后由已确认技师开始。从实际开始计算完整时长，晚开始需重新检查闭店、下一单和资源                                                                  |
| 资源释放   | 取消、保留超时、结算保留主动释放均释放相应资源；实际结束后计入清场，等待验收不继续占床                                                                                       |
| 店内日历   | 店铺按床位/独占房间查看结算保留、预约、签到、服务中及清场；超时未结束的服务仍显示占用，技师可查看本单接待位置                                                                |
| 未到店     | 店铺或合法技师记录联系、等待后申报，店铺核实；申报后顾客有 30 分钟回复期，回复即不能按未到店收费；签到可撤销待核实爽约。未扫码不会自动产生收费                               |
| 迟到       | 顾客晚于预约时间核销、且在到店那一刻已无法提供完整时长时，店铺可按下单时取消政策（视同开始时取消）关闭；店铺自身拖延造成的无法开始不能这样收费                               |
| 平台监控   | 区分到店情况待核实、签到后等待服务，避免误报为上门技师迟到；投诉与安全通道继续保留                                                                                           |
| 通知       | 已确认到店预约增加一次临近提醒；已有通知适配器可发送预约时间、门店及电话。未配置适配器时仍为本地队列，不能视为真实送达                                                       |
| 用户 H5/PC | 首页、项目、技师、店铺浏览增加模式切换；详情、报价选择、结算、订单、核销、再次预约按方式显示，保持日/英/中三语                                                               |
| 经营       | 报表增加上门/到店分组，订单导出追加服务方式列；既有时间方式分组和金额口径保留                                                                                                |

到店没有引入假的“技师已出发/已到达”。订单主体保持现有状态，增加独立 `checkIn` 核销事实：`CONFIRMED + checkIn → IN_SERVICE → AWAITING_COMPLETION → COMPLETED`。

## 2. 两项验收问题已修复

1. 自动验收检查订单关联的未解决普通售后工单和开放安全事件。普通服务质量及安全投诉都能阻断；完成面板从服务端读取当前是否允许自动验收。
2. 新报价记录 `completionPolicy.version=silence-72h-v1`。旧单无此版本时继续转人工复核，不按旧 24 小时截止时间执行新的自动验收；三语面板相应显示人工处理说明。

新的自动验收还保留足时、无既往验收异议/异常、有效且属于本单的授权与额度等检查。仅用户显式确认和适用新政策的合格订单进入既有模拟记收流程。

## 3. 操作入口

1. 店铺端 `/{locale}/merchant?tab=settings`：到店服务设置，提交真实接待资料、营业日历和接待单元；设置技师可服务方式和到店菜单。
2. 平台端 `/{locale}/admin?tab=review`：到店门店审核，填写审核说明后通过或要求修改。
3. 用户端 `/{locale}?fulfillmentMode=IN_STORE`：选项目、技师或店铺，预约到店；到店首版仅指定时间。
4. 用户订单 `/{locale}/account/bookings/{id}`：查看地点、导航、联系电话及本人核销码。
5. 店铺订单：输入顾客出示的核销码；技师端在确认签到后开始、结束，顾客端验收或提出异议。
6. 店铺团队日历 `/{locale}/merchant?tab=schedule`：按日查看各接待单元的预约与占用，记录可直接打开对应订单；不返回顾客姓名、电话或核销码。

切换服务方式会清除不兼容的项目和时间选择，并重新请求供给；不会复用另一种方式的报价/保留。已提交订单的服务方式有数据库不可变保护，换方式需按现有政策取消重下。

## 4. 新增与扩展接口

| 方法与路径（均以 `/v1` 开头）                        | 权限与输入                                                                                                                |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `PUT merchant/venue`                                 | 本店商户；门店完整资料和当前 `version`，首次 0；提交后 `PENDING`                                                          |
| `POST merchant/venue/photos`                         | 本店商户；`{ mime: image/jpeg或image/png, data: base64 }`，不超过 350 KB，服务端重新编码并去除元数据，返回 201 和照片地址 |
| `GET public/venue-photos/{id}`                       | 仅当照片属于已通过审核的现行门店时公开；上传店铺和平台审核员登录后可预览未审核照片                                        |
| `POST merchant/bookings/{id}/late-arrival`           | 本店商户；`{ version, note }`，顾客迟到无法完整服务时按取消政策关闭，原因为 `CUSTOMER_LATE_ARRIVAL`                       |
| `GET merchant/venue/calendar?date=YYYY-MM-DD`        | 本店商户；日本日期，返回接待单元及其预约、临时保留和清场记录，不含顾客联系方式或核销码                                    |
| `PUT merchant/home-visits`                           | 本店商户；`{ version: store.ruleVersion, enabled }`；可先暂停上门再申请到店，不影响已接订单                               |
| `GET admin/venues`                                   | 平台 `supply.read`；返回门店审核记录                                                                                      |
| `POST admin/venues/{storeId}/review`                 | 平台 `supply.write`；`{ version, decision: APPROVED/REJECTED, note }`                                                     |
| `PUT merchant/team/{listingId}/service-modes`        | 本店商户；`{ version: serviceModesVersion, modes }`，首次版本 0                                                           |
| `POST merchant/services/{sourceOfferingId}/in-store` | 本店商户；`{ version: source.version, price, active? }`，创建独立到店价目，返回 201                                       |
| `POST merchant/bookings/{id}/check-in`               | 本店商户；`{ version, code }`，核对顾客出示的 12 位核销码                                                                 |
| `GET public/staff-listings`                          | 增加 `fulfillmentMode`；缺省上门，`IN_STORE` 到店，`ALL` 用于详情/跨方式选择                                              |
| 人员/店铺可约、H5 技师目录                           | 增加 `fulfillmentMode`；到店仅 `SCHEDULED`                                                                                |
| `POST quotes`                                        | 增加 `fulfillmentMode`，缺省上门；到店地区来自审核门店，不要求顾客地区                                                    |
| `POST bookings`                                      | 上门仍必须合法 `address`；到店必须 `contact: { name, phone }`，不接受顾客住宅地址代替门店                                 |
| 完成确认读取                                         | 增加 `autoConfirmationEligible`，界面据此显示自动/人工验收提示                                                            |

新增业务错误包括 `INVALID_PHOTO`、`PHOTO_LIMIT`、`NOT_LATE`、`SERVICE_STILL_POSSIBLE`、`VENUE_UNAVAILABLE`、`RESOURCE_UNAVAILABLE`、`VENUE_HAS_BOOKINGS`、`CONTACT_REQUIRED`、`INVALID_CHECK_IN_CODE`、`INVALID_TRANSPORT_FEE`。存在预约时不能移走地点或移除其已保留的资源。

联系人、电话与核销码随订单私密字段加密保存；核销码不出现在店铺、技师、平台普通订单列表中。未确认人员或已失去任务访问的技师不能通过订单读取联系人。

首次使用需由店铺配置并经平台审核。现有演示库未自动增加“真实门店”或新交易，因此在没有通过审核的到店供给时，用户端会展示真实空状态。

## 6. 审查后修复（2026-10-26）

审查发现以下问题，已修复并补测试。每个新用例都做过回退检查：恢复原逻辑后对应用例失败。

| 问题                                                                                                   | 修复                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 上门技师迟到哪怕 1 分钟、下一单紧挨着时，系统拒绝"开始服务"（`SLOT_CONFLICT`），顾客在家等待却无法开始 | 上门不再因后续时段拦截开始；有空闲时才延长占用，否则保留原时段，下一单按既有延误/改派处理。到店仍要求完整时长放得下                                |
| 门店照片接受任意外部 https 链接，审核后可被换图，也会把顾客访问泄露给第三方                            | 照片必须上传到平台（JPEG/PNG，服务端重新编码、去除 EXIF 位置）；只能使用本店上传的照片；未审核照片仅本店与审核员可见。照片文件随备份一并导出和恢复 |
| 门店任何修改都重置为待审核，到店预约整体下线，结算中的顾客下单失败                                     | 现行门店保持可预约；地址等事实进入草稿待审，营业设置立即生效；驳回不影响现行门店；相同内容重复提交保持驳回。批准地址变更时若已有预约会被拒绝       |
| 一单超时未结束，会让该技师和床位之后所有日期都不可约                                                   | 超时服务视为仍在进行，只占用此后一段缓冲时间，不再隐藏以后的日期                                                                                   |
| 跨午夜门店的休息日按日历日判断，周五夜里 01:00 被拦、休息日当夜 01:00 反而可约                         | 休息日按营业日判断：跨午夜的夜间时段属于开门那一天；24 小时门店仍按日历日                                                                          |
| 到店顾客迟到无法完整服务时没有处理出口                                                                 | 新增迟到关闭：以服务端核销时间证明迟到，并按核销时刻判断是否已无法完整服务，避免把店铺拖延转嫁给顾客                                               |
| 到店未到店由店铺一方完成联系、申报和收费确认                                                           | 申报后给顾客 30 分钟回复期，期间不能确认收费；顾客回复即阻止收费；顾客端显示回复说明和截止时间                                                     |
| 修改营业时间或休息日可能让已确认的预约落在营业时间外                                                   | 保存时检查未开始的到店预约，落在新时间外则拒绝并提示先处理                                                                                         |

另外：隔离冒烟改为使用临时证据目录，测试上传不再写入开发数据目录；到店冒烟增加照片上传、可见性和审核期间继续接单的 HTTP 检查。

仍需注意：PostgreSQL 上的新触发器和资源并发路径尚未在目标数据库实测；到店界面尚未做真机逐页点击验收。
