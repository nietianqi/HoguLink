# 第十轮：员工账号、角色权限与指定分派

2026-10-18。平台内部员工使用 ADMIN 身份下的岗位角色，与提供上门服务的 STAFF 技师账号分开管理。界面延续深绿、暖白与细分隔线，支持日语、英语、中文及 PC/H5。

## 参考

参考 [Zendesk 员工与工单访问](https://support.zendesk.com/hc/en-us/articles/4408886939930-Adding-agents-and-admins-and-setting-ticket-access) 对岗位、组别和访问范围的划分，以及 [组内分派权限](https://support.zendesk.com/hc/en-us/articles/4408834893978-Enabling-agents-to-assign-tickets-to-their-groups)。依据公开官方说明实现项目自己的流程，未访问竞品受保护后台。

## 账号流程

1. 负责人在“员工与权限”填写姓名、工作邮箱、岗位和业务组，创建 INVITED 账号。
2. 一次性展示 72 小时有效的邀请链接，服务端只保存令牌摘要；提供复制入口，标明 MANUAL_LOCAL_ONLY，没有发送邮件。
3. 员工打开链接核对邮箱，设置 12–128 字符密码，激活后通过员工登录页进入后台。密码以独立随机盐和 scrypt 派生保存；已使用、过期和被替换的令牌不能激活。
4. 负责人可修改资料、角色、组别和启停状态。修改须填写 10–1000 字原因并检查版本，使旧会话失效；邮箱作为固定账号标识。
5. 停用清除旧密码和未使用邀请资格。重新启用进入待激活，需重新邀请并设置密码。“重发邀请 / 重置访问”也立即作废旧密码、链接和会话，界面展示影响并要求原因。
6. 当前操作账号及受保护的本地演示负责人不能自行停用、降权或重置，避免误操作锁住入口。账号历史保留，员工列表展示真实状态、登录时间、邀请期限和过期提示。

会话为 12 小时 HttpOnly / SameSite=Strict Cookie，每次请求核对当前员工状态和会话版本。账号请求有频率限制，登录失败不区分账号不存在、停用或密码错误。账号操作履历仅负责人可读；通用审计只写事件引用，不复制邮箱、密码、令牌或原因原文。会话失效时前端清理身份和私密工作区。

## 固定角色

| 岗位       | 能力                                                | 工单范围                      |
| ---------- | --------------------------------------------------- | ----------------------------- |
| 平台负责人 | 全部后台与员工管理                                  | 全业务组                      |
| 运营人员   | 订单、供给审核、工单处理/分派、审计                 | 配置的组                      |
| 客服人员   | 订单、认领和处理本人负责的工单                      | 客户支持 / 商家运营中配置的组 |
| 安全审核   | 订单、供给查看、工单处理/分派、安全处置、限制、审计 | 信任与安全组                  |
| 财务人员   | 查看订单、财务账目                                  | 无工单访问                    |
| 只读审计   | 查看订单、供给、财务、审计、系统                    | 无工单访问或修改能力          |

当前为六种固定岗位，权限页逐项展示能力。处理岗位必须加入至少一个允许的组；客服不可加入安全组，财务/审计不配置处理组，负责人自动具备全部组。前端按权限显示入口和按钮，服务端独立授权。快照按岗位限制财务、工单、安全、审核、审计和通知记录；旧 dashboard 聚合入口限定负责人，避免绕过新权限。

## 指定分派与离岗交接

- 内部处理面板新增“指定员工分派”，仅具备分派权的人可用。候选必须已激活、在职、具备处理权限且属于目标组，并展示未结工单数。待激活、停用、只读、未知或错误组的账号均不能接单。
- 分派检查工单版本及内部处理版本，防止并发覆盖。普通客服可认领待分派工单、释放自己负责的工单，回复与结案要求本人已认领；不能更改他人安排。
- 有分派权的运营/安全员工仍受所属组约束。安全、隐私、资格、申诉类工单保持在安全组，不能通过转组开放给普通客服；越组详情返回 404。
- 停用、移组、降为只读或重置访问时，在同一事务内释放不再具备资格的未结工单：清空负责人，回到 TRIAGE，跟进时间设为当前时间，追加 OWNER_UNAVAILABLE 履历。
- 已结束工单保留历史负责人；重开时重新检查原负责人资格，失效则回到待分派。内部履历展示操作人、当时负责人、组别、阶段和依据，相关历史可辨认离岗人员。
- 候选目录不返回邮箱或凭据；员工姓名、内部安排、备注不会复制到顾客/店铺可见的普通工单消息。真实通知仍待集成。

## 入口与接口

入口：`/{locale}/admin?tab=members`、`/{locale}/admin/login`、`/{locale}/admin/activate?token=...`。登录/邀请页 noindex；邀请页禁止发送 referrer。

| 方法 | 路径（省略 /v1）               | 输入或返回                                       |
| ---- | ------------------------------ | ------------------------------------------------ |
| GET  | /admin/members                 | 负责人；员工、角色权限、最近 100 条账号履历      |
| POST | /admin/members                 | name、email、adminRole、teams；返回单次邀请      |
| PUT  | /admin/members/{id}            | version、name、adminRole、teams、enabled、reason |
| POST | /admin/members/{id}/invitation | version、reason；重发 / 重置访问                 |
| POST | /auth/employee/invitation      | token；检查邀请，返回受邀姓名、邮箱              |
| POST | /auth/employee/activate        | token、password；单次激活                        |
| POST | /auth/employee/login           | email、password；建立会话                        |

内部处理接口支持 `ownership=ASSIGN`、`assigneeId`，其他 ownership 不接受 assigneeId。GET handling 增加可用 assignees 及相关历史姓名 people，均保持管理员授权。所有写接口保留 Origin 校验。

主要实现：`employees.ts`、`admin-access.ts`、`ticket-handling.ts`、contracts、`admin-members.tsx`、`admin-access-form.tsx`、`member-i18n.ts`。

## 验收与边界

- **141 项测试**：118 后端、23 前端；本轮新增 14 后端、2 前端。类型检查和生产构建通过。
- **542 项隔离 HTTP/SSR 检查**：原有 452 + 本轮 90。覆盖邀请、密码、重复邮箱、权限与组隔离、分派资格、停用、重新激活、会话撤销及页面隐私标记。
- **84 组页面**：三语言四尺寸的员工/角色/履历 36 组，登录/无效邀请/工单详情 36 组，六种角色 PC/手机 12 组。无脚本异常或横向页面溢出；320px 邀请弹窗和 Escape 恢复滚动通过。
- 浏览器完成邀请→激活→员工登录→指定分派→员工回复→停用→旧会话清理→工单退回。测试员工及工单仅在独立内存 API，测试未修改主库订单、审核或支付；主库初始化受保护的本地演示负责人。截图位于 `.playwright-mcp/people-*`。

本轮是可持久化的本地账号与授权流程。公开演示负责人入口继续用于本地体验，不能用作生产权限隔离；现有保护仍拒绝生产模式启动。正式部署需关闭演示认证，接入受控负责人引导、SSO/MFA、邮件投递、密码恢复验证、持久化登录风控与安全存储。本轮未向真实员工发送邮件或消息。
