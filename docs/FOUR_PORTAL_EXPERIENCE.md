## 评价与复购规则

1. 一单一条评价，服务端从订单推导顾客、原店铺、实际服务人员、服务名称及监管类目。新报价保存名称和类目快照；旧订单兼容原数据。仅 `COMPLETED`、曾经扣款且属于已开放的放松类服务可评价，退款不会自动抹去真实服务反馈。
2. 五维为准时、沟通、说明、清洁、整体，各1–5整数；不默认预选五星。文字最长600字。联系方式、部分房间标识、外貌和医疗宣传有基础拦截，全部内容仍需人工审核；基础规则不是完整内容识别服务。
3. 新增或编辑变为 `PENDING`，旧内容停止公开；通过后计入统计。修改推进内容修订号，旧店铺回复不会套用到新评价。撤回立即停止公开，保留私有修订记录供售后核验。
4. 店铺不能读取未公开顾客评价，不能自行删除差评。回复为独立的 `PENDING → APPROVED/REJECTED` 记录。复核申请不隐藏原评价，同一修订只可申请一次；平台检查事实后保留或移除。顾客修改或撤回会让旧复核申请失效。
5. 公开 DTO 不包含顾客、订单、实际人员身份字段。技师仅见本人当前所属店铺的匿名反馈；换店不会迁移旧店评价。审核备注和申诉材料不进入公开列表或通用审计文本。
6. 收藏采用顾客＋店铺人员档案关系和版本保护；对象授权撤回、资质或关系失效时，收藏页隐藏旧姓名和肖像，仍可移除。复订不迁移到其他店铺；原指定服务不可约时提示重新选择，不静默更换技师。非指定单只可在原店铺中选择当前合格人员。
7. 复订只带当前服务、地区、语言、指名方式等选择项；不带旧报价、保留、付款、地址或时段。必须重新选时段、确认价格和条款。

## 即时履约与取消

- 新报价 `demo-policy-v3` 快照即时单规则：出发前免费，出发后只收约定交通费；服务方原因及超过原到达承诺＋15分钟仍未到达免费。旧订单保留原政策。
- 首次确认保存原承诺到达时间。技师在出发前或途中可以报告交通、上一单延时、交通工具异常或其他原因，预计5–180分钟；改派或更新预计不会延长原迟到门槛。
- 迟到达到门槛记录一次本地通知事件。技师已到达后的爽约继续走已有等待、联系留痕和店铺核实流程，不因为报告本身自动收费。
- 顾客先请求服务端取消预览，确认携带订单版本和预期费用。进度或费用变化后拒绝旧确认，必须刷新重新确认；服务中不提供顾客直接取消，改走店铺或售后处理。
- 取消后的部分扣款、剩余保障作废与平台费为零沿用原交易模型。模拟支付事实不代表真实 PSP 已接通。
- 正在服务的技师在原占用区间结束后仍不计入即时单容量，公开状态、时段查询、报价和保留同时检查；未来指定时间预约继续按日历与缓冲区间判断。

## 安全签到与升级

`IN_SERVICE` 到计划结束＋15分钟发起 `WAITING`；5分钟未回应升级为 `ESCALATED` 并创建平台安全事件。本地后台定时检查间隔15秒，接口访问也会检查到期，实际展示可能略晚于规则时间。

- 技师确认安全后，如服务仍未结束，15分钟后再次确认，不能一次签到永久关闭监测。
- 主动请求协助立即创建 SOS；若已有签到超时事件，原事件升级为 SOS 并推进版本，不创建重复事件，旧平台处理请求因此失效。
- 升级后补签安全不会自动关闭事件；店铺只能记录联系情况。平台核实后确认完成。服务完成也不会自动抹去未处置的升级事件。
- 顾客无权读取签到队列；店铺仅见本店，技师仅见本人当前有效任务；店铺联系说明不向技师公开。历史保留在私有记录中。
- 不持续定位或录音。当前通知只进入本地队列和工作台，不发送真实 SMS/LINE，不提供人工紧急响应；页面明确展示该边界。

## 接口与实现

新增接口统一在 `/v1` 下，身份、店铺和实际服务人员均由服务端验证：

| 方法      | 路径                                              | 用途                                     |
| --------- | ------------------------------------------------- | ---------------------------------------- |
| GET       | `/public/experiences?listingId=…` 或 `?storeId=…` | 六条分页、已审核公开内容和真实汇总       |
| GET / PUT | `/customer/favorites/{listingId}`                 | 当前收藏状态；版本＋active更新           |
| GET       | `/customer/favorites`                             | 当前可用收藏；失效档案去标识             |
| GET       | `/customer/bookings/{id}/experience`              | 本人评价资格与当前记录                   |
| PUT       | `/customer/bookings/{id}/review`                  | 五维、文字、版本；服务端推导归属         |
| POST      | `/customer/reviews/{id}/withdraw`                 | 本人撤回                                 |
| GET       | `/customer/bookings/{id}/rebook`                  | 当前原店铺供给重新选择参数               |
| GET       | `/merchant/experience`、`/staff/experience`       | 分角色匿名反馈                           |
| POST      | `/merchant/reviews/{id}/reply`、`/appeal`         | 独立回复和私有复核申请                   |
| GET       | `/admin/experience`                               | `supply.write` 审核队列和处理历史        |
| POST      | `/admin/experience/{REVIEW\|REPLY\|APPEAL}/{id}`  | 版本、决定、四项检查和处理说明           |
| GET       | `/bookings/{id}/cancellation-preview`             | 本人或本店服务端费用预览                 |
| POST      | `/customer/bookings/{id}/cancel`                  | 新页面同时提交 `expectedFee`，旧调用兼容 |
| GET       | `/fulfillment/safety`                             | 本人/本店或 `safety.write` 平台私有队列  |
| POST      | `/fulfillment/bookings/{id}/delay`                | 技师更新预计到达及原因                   |
| POST      | `/fulfillment/bookings/{id}/check-in`             | 技师安全或协助回应                       |
| POST      | `/fulfillment/bookings/{id}/contact`              | 本店私有联系结果                         |

核心代码为 `hogulink-api/src/experience.ts`、`fulfillment.ts`、`engine.ts`，共享类型在 `packages/contracts/src/experience.ts`；页面组件为 `experience-ui.tsx`、`quality-workspace.tsx`。继续复用原平台安全处理接口与员工权限体系。

## 本轮验证

- `npm run check`：335项测试（310项后端、25项前端规则）、严格类型检查和 Next 生产构建通过。
- `npm run smoke:isolated`：原545项＋新增56项，共601项 HTTP/SSR 断言通过。
- 浏览器：78组页面＋18组弹层，共96组，覆盖三语言、320/390/1440宽度，无横向溢出或页面脚本异常；弹层焦点、Escape、16px表单通过。
- 实际操作：评价提交、审核必填、审核公开、店铺回复重审、匿名展示、收藏持久化、复订新报价入口、迟到免费取消、店铺联系、技师补签、平台处理、申诉保留，以及并发评价编辑重新打开最新内容。
- 写检查均在独立内存库执行；预览库 `hogulink-api/data/hogulink.sqlite` 未写入测试数据。自动化记录和截图在 `.qa/four-portals/`。
