## 2. 限时优惠（店铺自行发起）

| 规则     | 值                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------- |
| 时长     | 1 小时 ～ 14 天，30 天内开始                                                                          |
| 价格     | 低于当前原价，且 ≥ 原价 30%，≥ ¥500                                                                   |
| 适用     | 活动期间**报价**的订单按限时价；报价冻结 `promotionId` 与原价                                         |
| 下单     | 报价有效期内活动刚结束，仍按已报价格；店铺提前结束或改价 → `PRICE_CHANGED` 重新报价                   |
| 改原价   | 结束当前优惠，`priceSince` 重新计时                                                                   |
| 划线原价 | 仅当原价已连续使用 ≥ 28 天，且近 56 天（含本次）优惠天数 ≤ 28 天时显示（景品表示法 二重価格表示指引） |

- 后端：`PUT/DELETE /v1/merchant/services/:id/promotion`（带 `version`，审计 `SERVICE_PROMOTION_SET / ENDED`）。
- 公开目录只返回进行中/已排期的优惠；`priceSince` 与历史窗口不对外。
- 商户端「服务项目」每项显示状态（进行中/已排期、价格、截止、是否可显示划线价及原因）和编辑弹层（东京时间）。
- 前台：首页「限时优惠」横滑区（无活动时整块隐藏）、推荐项目、`/services?promo=1` 筛选、技师目录、详情页服务菜单，统一用 `H5Price`：先显示实付价，可比较时才显示 `<del>` 原价与截止时间。
- 演示：`APP_MODE=demo` 启动时通过同一商户规则为示例店「空」90 分钟项目创建一次 7 天优惠（`meta: demo-promotion-v1`），测试库不受影响。

## 3. 真实口碑与单数

`GET /v1/public/listing-stats?ids=a,b`（≤ 50 个，仅已上架技师）及目录 `stats` 字段：

- 评分 / 评价数：仅已审核通过的体验评价（`APPROVED`）。
- 近 90 天完成单：`COMPLETED` 订单按指派技师统计。
- 收藏数：有效收藏。
- 无评价显示「暂无评价」，不填默认分。目录新增「评分优先」排序（评分 → 评价数）。
- 统计使用只读数据库聚合和技师/状态联合索引，不解码无关评价或扫描完整收藏、订单正文。普通排序只统计当前页；评分排序先聚合全部匹配技师再分页。近 90 天按 `completedAt`（旧记录回退 `updatedAt`）计算，改派订单计入实际履约技师。

## 4. 标签

- 免交通费：当前展示项目 `transportFee === 0`。
- 可即时上门：对当前展示项目、地区和语言查询真实即时空档，同时通过在岗有效期、店铺授权范围、当日上限、资格与冲突校验。其他项目可即时预约不会使当前项目误标；详情页使用同一可约接口。
- 限时优惠：存在进行中的优惠。
- 不提供「新人」「人气」「颜值」等标签（PRD §51）。

## 5. 距离（位置不上传）

- 用户点「附近」才请求定位；坐标四舍五入到约 100 m，只存本标签页 `sessionStorage`（30 分钟）。
- 浏览器内计算最近的服务区（5 个区役所中心点），只把区名作为 `near=<ward>` 发给服务器用于 `sort=distance`；URL、请求均不含坐标（已用网络记录核对）。
- 卡片显示「距台东区中心约 1.6 km」——因只有区中心点、没有边界，不声称「在服务区内」。
- 拒绝定位：提示手动选择地区；距离超过 15 km：提示已按最近服务区排序。
