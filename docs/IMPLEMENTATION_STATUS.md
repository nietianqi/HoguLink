## 当前：业务规则修订（2026-10-26）

根据各端业务逻辑审查（含 [产品业务审查](PRODUCT_BUSINESS_REVIEW_2026-10-26.md) 指出的问题）修正：

- **SOS 进入平台监控**：订单监控此前读取不存在的数据集，技师 SOS 不会出现在平台预警中。改为读取实际安全事件，处理后预警标记为已解决。
- **已受理待派技师预警**：店铺已受理但尚未安排技师的订单，临近响应期限时触发 `RESPONSE_DUE`（改派待顾客同意的除外）。
- **价格口径统一**：H5 技师卡价格计入地区交通费；PC 首页选择套餐时按含地区交通费的总价比较；“最低总价”排序按含附加费总价跨分页排序。
- **营业时间**：可约时段与报价校验统一为店铺营业时间（默认 9:00–22:00，可跨午夜或 24 小时），店铺端可编辑并预览；修复报价接口可预约深夜时段的问题。
- **即时单到达即开始**，结束仍按实际开始 + 购买时长校验。
- **远期支付保障（CP-44）**：授权有效期覆盖验收期才在下单时授权，否则上门前 48 小时预授权；失败后顾客 12 小时内重新认证，期间技师不能出发、顾客取消免费，逾期免费取消并释放时段。顾客端显示重新认证面板，店铺/技师端显示勿出发提示。
- **沉默视为验收**：服务结束 72 小时内无确认、无异议的合格订单自动确认并扣款一次；出现过异议或异常的订单不按沉默处理。顾客端三语告知。

验证：后端 685 项（新增 SOS、待派预警、跨页价格排序、营业时间、即时开始、预授权成功/失败/续期/逾期取消、后台唤醒、自动验收及异议阻断等用例，均做过回退变异检查：恢复旧逻辑后对应用例失败）、前端 119 项、18 组隔离 HTTP/SSR 共 1,812 项、类型检查与生产构建通过。冒烟脚本的预约时间改为落在默认营业时间内，避免夜间运行失败。主预览未写入。

## 第四十三轮预约至售后完整回归（2026-10-20）

按顾客实际路径回归选人、项目/时段、登录返回、地址校验、最终核对、提交、订单状态、足时履约后的用户验收、原订单售后、撤回、部分处理、工单跟进、再次预约及取消。顾客端操作通过浏览器完成；店铺/技师的受理与履约、时钟推进和模拟部分退款通过隔离 API 驱动，不声称经营端每一步都由浏览器点击。支付保障沿用既有模拟服务，没有接入或向真实支付渠道发起交易。

发现并修复五类问题：

- 公开技师目录读取失败会阻断私有订单。两者改为独立读取，即使目录请求尚未返回也先显示订单，目录只作资料补充；仍显示冻结服务、金额、政策和售后，缺失技师资料使用当地语言提示。
- 完成状态读取失败缺少明确重试，恢复后旧错误可能残留。补齐加载/重试和成功清错，确认操作受当前订单版本及同步提交锁保护。
- 售后刷新失败仍可按旧余额操作。旧金额保留作参考，申请与决定需成功读取当前快照；售后响应附订单版本，余额变化会同步原订单，避免拿新余额配旧版本提交。
- 新工单创建或列表切换后，详情和链接可能仍对应旧工单。顾客工单路由与所选记录同步，明确查询目标变化时重新初始化；创建增加重复提交保护和按内容复用重试键。隐藏顾客端技术版本文字，补充查看原订单入口。
- 保留时段倒计时依赖设备时间。确认页返回服务端当前时间，前端用单调经过时间递减；服务端与设备相差六小时的隔离浏览器复验仍正确显示约十分钟。

## 已知技术边界

所有写操作以进程队列串行化，PostgreSQL 还使用事务级 advisory lock。这是便于验证正确性的开发基线，吞吐有限，生产阶段应按资源锁定和规范化表拆分。SQLite 的 interval 冲突由插入触发器防守，现有 API 不提供任意 interval 更新接口。

演示支付与数据库在同一本地事务中模拟；没有向外部 PSP 发起调用。正式 PSP 必须在数据库事务外执行网络请求，再以幂等/补偿/outbox 完成一致性，不应直接把真实 PSP 调用替换进当前事务。

当前仍没有完整登录、商户/技师入驻与资料审批、真实法律文本、通知、支付回调与对账。服务价格、接单规则、人员不可约时间编辑已在第六轮补充。售后工单、顾客限制申诉与安全处置已在第二轮补充；所有上线依赖按开发计划 D/E 阶段完成后再开放真实交易。
