## 已知技术边界

所有写操作以进程队列串行化，PostgreSQL 还使用事务级 advisory lock。这是便于验证正确性的开发基线，吞吐有限，生产阶段应按资源锁定和规范化表拆分。SQLite 的 interval 冲突由插入触发器防守，现有 API 不提供任意 interval 更新接口。

演示支付与数据库在同一本地事务中模拟；没有向外部 PSP 发起调用。正式 PSP 必须在数据库事务外执行网络请求，再以幂等/补偿/outbox 完成一致性，不应直接把真实 PSP 调用替换进当前事务。

当前仍没有完整登录、商户/技师入驻与资料审批、真实法律文本、通知、支付回调与对账。服务价格、接单规则、人员不可约时间编辑已在第六轮补充。售后工单、顾客限制申诉与安全处置已在第二轮补充；所有上线依赖按开发计划 D/E 阶段完成后再开放真实交易。
