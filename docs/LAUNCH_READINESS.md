# 上线准备：平台端与技师端完善（2026-10-26）

本轮按产品审查清单补齐平台端与技师端功能，并整理上线前提。结论先写在前面：**现在可以按 staging 方式上线试运营**（真实账号、真实邮件、真实店铺和技师入驻，支付为模拟）；**收真钱的正式上线**仍需接入支付、身份核验和即时通知，代码在生产模式下会主动拒绝启动，避免误用模拟支付。

## 1. 本轮完成

### 安全（两端共用）

| 功能             | 行为                                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| SOS 求助面板     | 技师按 SOS 后显示 110/119 拨号、店铺紧急电话                                                                                         |
| 位置共享         | 技师本人点击后共享一次当前位置；只有店铺和平台安全团队可见；事件结束后不再显示；加密存储                                             |
| 紧急查看服务地点 | 平台安全团队在事件处理中填写原因后可查看服务地址（上门地址或到店门店）、店铺紧急电话和共享位置；每次查看写入审计；事件结束后不可查看 |

### 技师端

| 功能         | 行为                                                                                                                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 出勤班次     | 每周固定班次（可跨午夜，归属开始当天）＋按日期调整；技师和店铺都可编辑；报价、可约时段、改派候选只落在班次内；不能删掉已约预约所在的时间；即时单仍按上班状态；未设置班次的技师沿用原规则 |
| 安全接单条件 | 「深夜（22:00–6:00）上门只接本店老顾客」：技师申请、店铺批准后生效，取消立即生效；指名时给顾客明确提示；店铺安排和改派也会过滤                                                           |
| 到店核销     | 没有前台的店铺，负责技师可凭顾客核销码核销；其他技师不行                                                                                                                                 |

### 平台端

| 功能         | 行为                                                                                                                                                        |

| 投诉证据照片 | 能查看工单的人可上传最多 10 张照片，服务端重新编码并删除位置信息；查看遵循工单可见范围；随备份导出与恢复                                                    |

| 店铺履约质量 | 近 30 天每店订单、完成、店铺原因未成单、店铺发起的顾客收费、异议、投诉、安全事件；订单满 10 笔且超过初始阈值时标记需跟进（阈值待用运营数据调整）            |

| 权限修正     | 门店审核接口此前误落入"仅平台所有者"；现在运营岗（supply 权限）可审核，客服岗不能修改                                                                       |

### 位置（全部免费，未使用付费 API）

| 功能     | 行为                                                                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 门店定位 | 店铺填写地址后点「根据地址查找位置」，服务端调用国土地理院免费地址检索填入经纬度（仅日本范围），并可在地理院地图上核对；检索不可用时提示手动填写 |
| 离店距离 | 顾客授权定位后，门店信息显示「距您约 X 公里（直线）」，在顾客浏览器内计算，位置不上传                                                            |

## 2. 现在可以上线的方式：staging 试运营

API 只接受 `APP_MODE=demo` 或 `APP_MODE=staging`。staging 启动时强制检查：

- `DATABASE_URL`（PostgreSQL）、`WEB_ORIGIN` = `PUBLIC_WEB_URL`（同一 HTTPS 域名）、32 字节 `DATA_ENCRYPTION_KEY`
- `DEMO_ACCESS_ENABLED=0`、`PAYMENT_PROVIDER=demo`（明确为模拟支付）
- `EMAIL_PROVIDER=resend` 及其密钥、发件地址
- `OPS_NOTIFICATION_EMAIL`：SOS、安全事件与超时预警发送到这里。**本轮起 staging 必填**

部署沿用 `compose.staging.yaml`；照片与证据保存在已持久化并纳入备份的 `private_evidence` 卷。第一个平台负责人用 `maintenance bootstrap-owner`（`ADMIN_BOOTSTRAP_EMAIL`、16 位以上 `ADMIN_BOOTSTRAP_PASSWORD`）创建，首次登录时页面会要求设置身份验证器；已有数据升级后运行一次 `maintenance migrate-private`，把新增的加密字段（安全事件位置、验证器密钥）重写为加密存储。

## 3. 正式收费上线前必须完成

| 事项                                                 | 原因                                                                                                   |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 接入支付服务商（PRD 首选店铺为收款主体的平台型 PSP） | 目前与信、扣款、退款均为模拟                                                                           |
| 真实身份核验（eKYC）                                 | 深夜首单 L3、实名等规则依赖；目前顾客均为基础登录                                                      |
| 即时通知：短信/电话/推送或 LINE                      | SOS 与 5 分钟即时单目前只发邮件                                                                        |
| PostgreSQL 实测                                      | 新的数据库触发器与资源并发只在 SQLite 上验证                                                           |
| 真机逐页验收                                         | 三语 PC/H5 关键路径需人工点击确认                                                                      |
| 法务确认                                             | 反社核查方式、风营法与店铺型门店、あはき资质、取消/爽约/迟到收费条款、隐私政策、国土地理院检索使用条款 |

## 4. 仍待决定

- 「仅接女性顾客」：需先决定是否及如何收集顾客性别资料。
- 「仅接已实名顾客」：依赖 eKYC，上线 eKYC 前开启会让技师无法被预约，因此暂不提供。
- 店铺质量阈值、违规分级处罚：需用试运营数据校准后再接处罚。
- 门店地图拖动定位：当前为地址检索＋地图核对＋手动修正，未引入地图组件。
