# 店铺端业务与界面迭代

日期：2026-10-18。入口：[中文店铺工作台](http://127.0.0.1:3000/zh-cn/merchant)。支持日语、英语、简体中文与桌面/手机布局。

## 同行参考

- [Fresha 官方知识库](https://www.fresha.com/help-center/knowledge-base)：区分预约、团队、服务、财务与设置。
- [Fresha 不可约时间](https://www.fresha.com/help-center/knowledge-base/calendar/18-set-up-and-manage-blocked-time)：用休息、请假等明确原因管理人员时间。
- [Fresha 服务目录](https://www.fresha.com/help-center/knowledge-base/catalog)：服务价格与可预约状态管理。

采用适合本项目的信息组织方式，继续使用 HoguLink 的店铺履约、技师确认、支付授权与安全规则。没有复制竞品标识、人物、评价、经营数字或银行到账承诺。

## 页面与业务

| 功能区     | 实现                                                                                                                        |
| ---------- | --------------------------------------------------------------------------------------------------------------------------- |
| 经营概览   | 今日预约、待处理预约、有效公开技师、实际模拟扣款净额；近 7 日按创建时间统计的预约量、未来有效预约与售后入口，无数据展示空态 |
| 预约管理   | 原有状态/日期/搜索、分页和详情；人工受理、FREE 派单、指名改派；取消/拒单先复核，退款支持填写部分金额                        |
| 团队日历   | 按日本时间查看人员预约和不可约时间；按技师筛选，从预约跳至对应订单。手机在日历容器内横向滚动                                |
| 休息与请假 | BREAK/TIME_OFF/TRAINING；保存后直接减少公开可约时段，可解除；不能覆盖预约、交通缓冲、checkout hold 或其他不可约时间         |
| 技师团队   | 公开条件、身份核验、肖像授权、有效归属、语言、项目和待机；进入单人日历。商家不能代替技师开启即时待机                        |
| 服务项目   | 修改已审核 RELAXATION 项目的含税服务费、交通费，暂停/恢复新预约；不能自行授予资质、改变审核状态或编辑其他店铺服务           |
| 财务与计费 | 同一事务内汇总扣款、退款、平台费与扣费后参考额；计提/冲回明细与时间；CSV 保留真实负数并防止文本公式注入，不含姓名和地址     |
| 店铺设置   | 版本化编辑 MANUAL/AUTO_PREAUTHORIZED 与私密紧急联系方式；SOLO 经营结构保持独立审核边界；经营主体资料只读                    |
| 售后与安全 | 保留原有工单、拒接和安全处理权限，补全与新工作台之间的导航                                                                  |

通过 `?tab=overview/bookings/schedule/team/services/finance/settings` 定位功能区，`booking` 定位订单，`member` 定位团队日历。切换演示店铺先清空旧数据，再读取本店内容，旧异步结果不会覆盖新身份。

## 一致性

- 不可约时间与预约共用数据库占用区间。创建支持幂等键与输入绑定，解除检查本店权限和版本；到期由 sweep 归档并释放区间。
- 项目价格版本、店铺规则版本写入报价，在保留、读取确认页、支付保障、提交时重新核对。修改不重写已提交订单的金额和受理快照。未使用的旧保留仍可由顾客主动释放或按 TTL 到期释放。
- 可派人员由服务端核对店铺归属、公开条件、项目、语言、酒店限制、即时待机与整个缓冲区间；实际派发再次校验。
- 退款检查订单版本与剩余扣款余额，按原费用事实比例冲回。财务数字是演示交易事实，不代表银行到账余额。
- 未变更的价格/规则保存不增加版本。计费比例读取服务端配置；已扣款费用保留原冻结事实。

## 验收

- `npm run check`：73 项服务端 + 11 项前端规则测试，共 **84 项**，类型检查和构建通过。本轮新增 10 项服务端、3 项前端规则测试。
- `npm run smoke:isolated`：预约 72 项、售后 90 项、新店铺检查 53 项，共 **215 项 HTTP/SSR 断言**。覆盖租户隔离、排班幂等与冲突、候选人员、项目暂停/恢复、规则版本、冻结报价、部分退款和财务汇总。
- 三语言 × 七个功能区 × 320/390/1024/1440 px，共 **84 组页面组合**；售后三语言两种宽度另 6 组，顾客首页/详情/预约三语言另 9 组，合计 **99 组**无文档横向溢出或运行时异常。
- 浏览器实际验证：不可约时段使公开时间从 78 减至 75，解除后恢复 78；项目改价/暂停/恢复；受理规则切换与恢复；切换店铺；团队页进入单人日历；部分退款 1,000 日元；导出含 -88 日元冲回的 CSV。
- 人工店铺还完成“待受理 → 店铺受理 → 选择合格技师 → 派发 → 复核取消”，最终 CANCELLED、支付保障 VOIDED。

写操作使用独立内存 API，没有清空或修改主预览经营配置和订单。截图在 `.playwright-mcp/merchant-final-overview.png`、`merchant-final-bookings.png`、`merchant-final-services.png`、`merchant-final-finance.png`、`merchant-calendar-blocked.png`、`merchant-mobile-final.png`。
