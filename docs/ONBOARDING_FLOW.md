# 商户与技师入驻、邀请、资质与肖像授权

更新：2026-10-18。依据 V1.4 第 4、33.1、34、47、51 章及附录 A，实现可操作的本地演示闭环。外部文件作为产品需求依据；运行权限仍由应用自身的账号、角色与资源归属校验决定。

## 体验入口

- 商户入驻：[中文入口](http://127.0.0.1:3000/zh-cn/onboarding?role=MERCHANT)。选择“创建入驻账号”，使用邮箱及至少 12 位密码注册；已有演示店铺可从店铺工作台上方进入“入驻与资质中心”。
- 技师入驻：[中文入口](http://127.0.0.1:3000/zh-cn/onboarding?role=STAFF)。先领取店铺生成的邀请，再使用邀请指定邮箱的个人技师账号接受绑定。
- 平台审核：[供给与审核](http://127.0.0.1:3000/zh-cn/admin?tab=review) 顶部的“入驻与资质审核”。只有具备 `supply.write` 的在职管理员可查看材料和决定审核结果。
- `/ja/onboarding`、`/en/onboarding` 提供对应语言；PC 使用分栏、步骤与材料工作区，H5 使用横向步骤导航、单列表单和原生弹窗。各端保留深绿、暖白、细边框与现有工作台入口。

一个浏览器会话使用一个角色。体验商户、技师和平台的交接时，使用不同浏览器会话。邀请页面无需登录即可查看店铺、受邀姓名、遮罩邮箱及期限，但接受、婉拒必须登录对应个人账号。

## 商户办理

1. 注册独立商户账号，建立不可公开的店铺草稿。默认 MANUAL、TRIAL，不要求先付年费，不允许通过演示店铺切换器冒充新商户。
2. 填写法人或个体主体、法定名称、经营地址、正式联系与紧急渠道、实际服务内容、适用申报说明、区域、语言、三语店铺资料和首个店铺定价项目。
3. 上传、关联身份证明与经营材料；受监管服务另需资格材料。保存草稿支持分步补全；提交时统一检查必填、分类、材料及条款声明。
4. 阅读三语演示入驻条款，确认反社会势力排除声明。提交时保存申请修订快照及条款版本、申请人、服务器同意时间。
5. 平台逐项核对主体、服务实质、材料、公开内容、反社会势力审查记录和**模拟** PSP 收款路径，填写有效期及向申请人可见的理由。
6. 可通过、退回整改、拒绝；已通过申请可暂停。整改或拒绝后需要保存新草稿、重新提交；审核中的材料不能被静默改写。所有决定带版本校验。
7. 通过后启用演示店铺与首个已审核服务。没有满足资质、本人授权与发布条件的技师前，新店仍不会进入公开店铺目录。后续项目仍使用既有店铺服务管理及发布规则。

受监管类目可录入和提交材料，但普通审核不能批准上架。当前只开放已有规则支持的 RELAXATION；不能用重命名服务绕过类目限制。

## 邀请、绑定与技师办理

1. 商户在“邀请与绑定”填写技师本人邮箱和受邀姓名。邀请有效 72 小时、仅可领取一次；同时最多 50 条待领取邀请。
2. 原始凭证只随生成或重新生成的响应显示，数据库仅保存哈希。界面提供复制链接，**不自动发送邮件**。凭证放在浏览器 URL fragment，打开后从地址栏清除，不进入普通页面请求参数。
3. 支持查看状态、撤销、到期、婉拒及重新生成。重新生成立即作废旧链接；已经接受的邀请只能通过解除绑定结束关系。
4. 本人以指定邮箱的 STAFF 账号登录，明确确认任职或合作关系。当前每个技师账号只允许一条有效店铺绑定；跨店需要先结束现有关系。店铺不能代替技师领取邀请或同意肖像。
5. 接受后建立该店独立 listing，初始不可公开、身份未核验、肖像未授权。绑定形成不会直接赋予营业资格；SOLO 店增加人员时，在同一事务内退出 SOLO。
6. 技师填写本人审核资料、三语公开名与介绍、服务实质、服务语言和本店可承接项目，上传本人身份证明及拟公开肖像。
7. 本人对已保存的确切资料版本和照片另行授权，提交资质申请。商户只查看拟公开姓名、照片、介绍、语言、项目及审核状态，不能读取技师身份证明、审核姓名和私人联系材料。
8. 店铺确认公开内容或填写整改要求。平台只有在店铺确认、有效本人授权、有效绑定、店铺资质与收款路径均满足时才能批准技师，并发布公开展示。

商户可以解除绑定，需填写原因并核对未完成订单。服务器也提供本人结束绑定接口。解除后立即撤销本店工作访问与肖像展示；未完成预约保留原交易身份，交由商户通过既有改派、取消、退款流程善后。账号可以继续登录入驻中心接受后续邀请；直接打开工作区会回到入驻办理入口。

## 肖像授权与材料保护

- 授权独立于店铺邀请与平台资质审核，记录当前条款版本、资料内容哈希、本人、店铺/listing、起止时间、操作版本及不可覆盖的授权事件。
- 用途为该店展示和预约页面的姓名、肖像与介绍，不包含另行广告复用；本人可撤回。授权从当前时间开始，最长一年，过期自动失效。
- 修改申请资料会暂停展示、撤销旧授权、清除店铺内容确认，必须重新授权与审核。重新授权本身不会自动恢复已暂停的展示。
- 撤回或过期后，公开目录、新报价/下单及公开图片接口均受阻；仍有效的资质与绑定允许处理已经成立的合法服务。
- 资质过期或暂停后，拒绝新预约及尚待确认/出发/开始的相关任务，商户仍可善后取消。已开始服务的完成、安全及支付善后保持可处理。
- 敏感证明与上传内容存于私有记录，公开目录和共享审计/outbox 不包含文件正文、私人审核姓名、账号密码或邀请原始凭证。下载需要本人或审核权限；店铺仅可取得本店当前提交的公开肖像预览。
- 文件支持 PNG/JPEG/PDF，服务端单份最多 350 KB，检查类型与签名。H5/PC 可选择 10 MB 内照片，浏览器自动压缩；实测 6,111,495 字节压为 255,183 字节并成功关联。PDF 限 350 KB。
- 拟公开肖像还需服务端真实解码，限制输入像素、校正方向、缩放并重新编码 JPEG，剔除 EXIF/XMP/ICC 等元数据。格式损坏或伪装的肖像被拒绝；公开图片每次请求重新检查资格与本人授权，使用 no-store。
- 现有种子店铺和技师保留明确标注的演示档案；不为旧布尔字段伪造实名证据。技师可在中心补录或撤回本人肖像授权。

## 状态与接口

申请：`DRAFT → SUBMITTED → APPROVED / CHANGES_REQUIRED / REJECTED`；审核有效期结束为 `EXPIRED`，主动暂停或绑定结束为 `SUSPENDED`。重新办理均需新修订草稿并提交。申请、店铺内容确认、肖像授权及 listing 发布各有独立版本。

| 范围           | 主要接口                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------- |
| 账号           | `POST /v1/auth/partner/register`、`login`、`invitation`；现有 `auth/session` 与 `auth/logout`   |
| 本人资料       | `GET /v1/onboarding/workspace`；`PUT /v1/onboarding/application`；`POST .../application/submit` |
| 私有材料       | `POST /v1/onboarding/evidence`；`GET .../evidence/{id}`                                         |
| 邀请           | `POST /v1/onboarding/invitations`；`POST .../invitations/{id}`；`POST .../invitation-response`  |
| 本人肖像       | `POST /v1/onboarding/portrait-consent`                                                          |
| 店铺确认、解绑 | `POST /v1/onboarding/members/{id}/content`、`.../end`                                           |
| 平台审核       | `GET /v1/onboarding/reviews`；`POST .../reviews/{id}`                                           |
| 合法公开肖像   | `GET /v1/public/portraits/{listingId}`，仅返回当前允许公开的清理后图片                          |

## 验收

新增 26 项后端检查（15 个领域测试及包含 10 个子场景的真实 HTTP 测试），覆盖完整正向流程、整改/拒绝/暂停、版本冲突、邀请指定邮箱/单次/过期/轮换/婉拒、材料归属、账号边界、受监管类目拦截、授权与资质独立到期、存量服务/取消，以及肖像解码和元数据剔除。

- `npm run check`：296 项通过（271 后端、25 前端规则），类型检查、Next 生产构建通过。
- `npm run smoke:isolated`：原有 545 项 HTTP/SSR 断言通过；写操作只使用独立内存 API。
- 浏览器实际完成商户账号至技师公开的跨端办理，随后验证修改资料立即下架、重新授权/审核、撤回肖像、解绑与工作权限撤销。
- 116 组布局检查：商户/技师三步骤、三语言、四尺寸 72 组；注册登录 12 组；后台队列和资质弹窗 24 组；店铺资料确认与解绑弹窗 8 组。320/390/768/1440px 无文档或弹窗横向溢出，手机可见文本输入不小于 16px。
- 证据：`.qa/onboarding/check.log`、`smoke.log`、`browser-results.json` 与页面截图。测试账号、材料和邀请仅存在隔离环境，未写入预览主库。

## 尚待真实接入

目前仍为本地演示，生产启动继续拒绝：正式身份及邮箱核验、真实政府/资格机构与 PSP 加盟店审查、正式合同文本、邮件/短信/LINE 送达、私有对象存储与病毒扫描、资料加密/留存/删除策略、生产人员审核制度及真机验收尚未接入。入驻审核通过代表本地人工流程记录，不代表取得实际经营许可或通过外部 eKYC/PSP 审查。
