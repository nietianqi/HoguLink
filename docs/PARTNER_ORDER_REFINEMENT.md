# 店铺与技师订单体验统一（第二十八轮）

2026-10-18。沿用深松绿、暖白与香槟色，调整接单、改派、履约、原订单售后协作的信息与操作层级。三语言覆盖日语、英语、简体中文，适配PC、平板与手机。

## 本轮实现

- 店铺与技师共用订单主卡：冻结服务项目、购买时长、预约时间（JST）、地区、当前下一步、真实响应期限与五阶段进程。取消/拒绝/过期不绘制虚假的履约完成进度；改派待同意回到技师确认阶段，验收异议停在用户验收阶段。
- 店铺把受理、合格候选人、直接分配/指定改派放在详情顶部；明确用户同意及重新承接规则。取消和直接退款归入“订单例外处理”，原用户退款仍从关联工单审核。
- 指定订单默认折叠大列表，通过“切换或查找订单”展开，保留原有搜索、筛选和导出。手机端展开后可见原列表，修复旧样式继续隐藏列表的问题。
- 技师统一任务主卡、履约与验收、沟通与安全和内部协作入口。服务名称优先使用冻结报价，避免项目编辑影响已购订单展示。详细地址继续由服务端权限裁剪。
- 协作面板显示读取状态与错误重试，避免重复刷新；保留原始进程、关联顾客工单、技师事实回复和内部结案。协作待办新增回到原任务的入口。
- 改派待顾客同意时，店铺和技师状态文案与用户端一致。补充店铺身份选择的明确可访问名称。
- 预约尚未读完时展示加载状态，避免短暂误报“订单不存在或无权查看”和“暂无预约”。

服务端接单权限、候选人条件、并发版本、幂等、私有事实范围、时长门禁、用户验收和退款金额限制沿用现有实现。本轮没有接入真实支付或外部通知。

## 隔离浏览器验收

所有交易数据使用独立内存API与独立网页预览，未写入日常预览数据库。

1. 指定葵的预约：店铺提议澪→等待用户同意→撤回并重新选人→顾客明确同意→指名费500日元免除，总价8700调整为8200日元。
2. 澪确认承接后，才显示本次上门地址；依次出发、到达。早于预约开始的按钮禁用；实际开始后不足60分钟的结束按钮禁用。
3. 使用仅存在于隔离测试服务器的时钟推进，按实际开始+购买时长提交结束；订单进入AWAITING_COMPLETION，支付AUTHORIZED，已扣款0日元。
4. 用户勾选完成验收并核对8200日元后，订单COMPLETED且只扣一次8200日元；技师端在结束后隐藏详细地址。
5. 顾客从原订单申请1000日元退款；店铺在关联工单请求实际履约技师澪补充事实；澪回复，店铺记录内部结果。此时用户退款仍PENDING、工单NEEDS_MERCHANT，金额不变。
6. 原店铺从用户原工单部分退款600日元；服务订单保持COMPLETED，支付PARTIALLY_REFUNDED，已扣8200、已退600、剩余可申请7600日元，申请状态PARTIALLY_APPROVED。
7. 人工受理店铺“森”受理订单后，仅进入等待技师确认，不直接确认预约或扣款。
8. 不指定订单先要求店铺安排；分配葵后进入OFFERED，等待本人承接，指名费保持0。展开/切换列表在手机端可用。
