# 四端综合测试与修复（第四十四轮，2026-10-20）

本地顾客、店铺、技师、平台四端的核心业务回归通过。覆盖中日英、PC/H5 及平板断点。真实支付继续暂缓，本轮没有接入支付渠道、发送真实邮件或修改主预览业务数据。该结论适用于本地演示与隔离测试，不等同于生产环境上线验收。

## 发现并修复

| 问题 | 原因与结果 |
| --- | --- |
| 公开目录故障使店铺待接单列表显示为零 | 经营端订单先等待公开目录，目录失败后不读取订单。私有订单改为独立读取，公开资料和汇总作为可选补充；私有店铺/技师信息用于订单名称，暂停公开的资料也不会丢失。目录 503 下实际受理订单成功。 |
| 读取中短暂显示零订单、空列表 | 经营端队列和统计现在等待订单读取完成，读取失败保留错误，不把失败当成空结果。 |
| 技师消息失败显示“暂无消息”，仍可发送 | 消息区区分读取中、成功空记录、失败和已加载；增加三语错误及局部重试，读取失败时禁止发送，重试保留草稿。加入同步提交锁，避免连续点击重复发送。 |
| 工作台恢复后旧错误残留 | 店铺、技师、平台的读取错误与操作错误分开，读取成功后清除对应错误。店铺初次失败不再无限显示加载图标；权限失效时清理原工作数据。 |
| 登录初始化旧请求错误覆盖已恢复页面 | 订单加载等待会话读取完成，旧生命周期请求的错误不能写回当前页面。完整刷新后，目录 503 下仍能显示正确店铺和技师，且无残留错误。 |
| 技师资料首屏头像延迟加载警告 | 首屏头像明确优先加载，PC/H5 均正常显示，单独新页面复查无警告。 |

保留冻结报价、取消政策、订单版本、改派同意、足时履约和用户验收规则。顾客页面继续使用 H5 绿/薄荷/白卡片/橙色费用风格，三个经营工作台保持各自现有样式。

## 实际业务操作

本轮在 `3300/4300` 独立端口、内存数据库运行。测试订单、虚构地址、时钟和顾客验收/退款申请由隔离夹具驱动；以下经营端及顾客操作通过浏览器完成：

1. 店铺受理人工预约，技师确认承接，确认前隐藏详细地址，确认后显示履约地址。
2. 技师消息读取 503，修复前输入后可发送，修复后禁用并提供重试；恢复后保留草稿，发送成功。
3. 技师依次记录出发、到达；预约时间前禁止开始，开始后不足购买时长不能提交结束。推进隔离时钟至足时后提交结束，仍等待顾客验收且未扣款。
4. 技师手机申请未来休息，店铺批准后同步不可约日历；解除后恢复可约安排。
5. 顾客验收后申请演示退款 1,000 日元，店铺手机确认实际处理 500 日元；工单、原订单及余额一致显示部分处理、剩余 8,200 日元。无真实支付渠道交易。
6. 平台认领服务问题、记录内部备注、回复并结案；顾客看不到内部备注，重新申请处理后仍为原工单并回到平台队列。
7. 顾客完成五项服务评分并提交审核，显示待审核；本轮没有公开发布评价。
8. 演示财务经办访问员工管理时提示权限不足；非顾客身份无法直接读取顾客订单，登录后返回原订单。跨店铺、跨技师、员工权限及会话撤销由隔离业务检查进一步覆盖。

预约选时段、地址、最终核对、提交、取消、再次预约和顾客实际验收的逐步浏览器记录见第四十三轮 `design-qa.md`。本轮重新运行全部接口流程，并复查当前预约与详情页面，不把每一个接口断言计作一次浏览器点击。

另测 SQLite 内存引擎性能：30,000 笔历史订单时目录平均约 0.51ms，20 次并发目录调用总计约 11.8ms。本次未复现历史订单数量导致目录线性退化；这是引擎基准，未包含 HTTP、网络、真实数据库和多实例压力，不作为生产吞吐承诺。

故障注入仅存在于内存测试入口，需独立端口和随机令牌，生产启动不会导入。浏览器控制台历史包含故意制造的 503 和修改依赖数组时的开发热更新提示；完整刷新后的相关页面已复查，头像独立复查无警告。
