## 四端实际操作

测试订单由独立 API 夹具创建：人工受理、60 分钟指名服务、总额 8,700 日元，使用虚构地址。时钟只推进内存测试引擎，不修改系统时间。以下步骤通过浏览器完成：

1. **店铺受理 → 技师确认**：店铺受理后仍等待技师确认；确认前详细地址隐藏，技师确认承接后才显示履约所需地址。
2. **任务沟通**：注入消息读取失败，填写草稿后发送仍被禁用；解除故障并重试后草稿保留，发送成功。
3. **出发 → 到达 → 开始 → 足时结束**：预约时间前开始按钮不可用；开始后不足购买时长不能提交结束。达到 60 分钟后提交结束，进入等待顾客验收，详细地址再次隐藏，尚未扣款。
4. **顾客验收**：非顾客身份访问顾客订单要求切换登录；登录后返回原订单。验收弹窗显示金额，必须明确勾选已核对完成及足够时长后才能提交。确认后订单完成，模拟扣款为 8,700 日元。
5. **原订单售后**：顾客申请 1,000 日元，不自动取消订单或退款。退款未决定时店铺不能关闭工单。店铺确认模拟处理 500 日元，三端均显示部分处理、已退 500、剩余 8,200 日元。
6. **顾客重新申请 → 平台介入**：顾客从原退款工单申请重新处理，进入平台队列，已退金额保持。平台从优先队列进入同一工单，认领、记录内部备注、对外回复。
7. **调查结论 → 店铺执行 → 平台结案**：缺少店铺陈述时不能发布；补齐店铺陈述后，若未引用顾客最新的重新申诉，服务端拒绝并保留草稿。引用双方陈述、确认共享结论后发布；店铺提交执行回执，平台记录处理结果，顾客确认并关闭原工单。结案后内部安排只读。
8. **技师履约事实与可见范围**：技师在历史任务提交店内履约备注；顾客端看不到该备注或平台内部备注。技师结束后的地址仍隐藏；店铺端也不能看到平台内部备注。

浏览器没有对真实支付渠道发起交易。订单创建、报价、保留时段与模拟授权由夹具/API 回归验证，不将这些步骤算作浏览器完成的下单点击。

## 故障及恢复

| 故障 | 实际结果 |
| --- | --- |
| 技师任务消息 503 | 不能发送；局部重试成功，草稿保留 |
| 公开目录 503 | 技师私有任务与协作记录、顾客原订单仍可读取；顾客显示冻结服务和费用，资料缺失明确提示 |
| 技师工作台刷新 503 | 显示失败，保留已读取记录；恢复后刷新清除错误 |
| 技师统计 503 | 四项统计均显示「—」，提供重试；恢复后显示真实 0 评价、1 笔完成单、0 收藏 |
| 店铺统计 503 | 显示统计暂不可用，服务菜单和报价继续可用；原地重试恢复，不丢地区、项目和店铺安排 |
| 顾客完成状态及售后 503 | 原订单继续显示；完成状态有重试入口，恢复后轮询清错；没有成功读取售后快照时不提供退款申请，手动刷新后恢复正确余额 |

本轮为独立测试入口新增 `listing-stats`、`store-stats` 两种故障注入，未修改生产应用入口或业务 UI。该入口要求随机令牌、独立端口、内存数据库，并拒绝主 API 端口；生产启动不会导入。

## 环境、证据与边界
