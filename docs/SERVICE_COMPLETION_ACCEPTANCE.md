# 履约时间、用户验收与异常联动

2026-10-26 后续修复：新报价记录验收政策版本；无新版本的旧单不套用自动验收。自动验收同时检查普通售后未解决工单与开放安全事件，界面读取服务端 `autoConfirmationEligible`。到店在核销后开始，同样以真实开始时间和购买时长判断足时，不能按原预约结束时刻把迟到后的缩短服务算作足时。见 [首版实现记录](DUAL_SERVICE_MODE_IMPLEMENTATION.md)。

2026-10-18，第二十五轮。本轮将“技师完成即扣款”改为“足时履约 → 技师提交结束 → 用户确认 → 扣款”，保留现有 PC/H5 深绿暖白风格及日、英、中三语。

## 2026-10-26 修订：沉默视为验收、即时单到达即开始

- 确认窗口由 24 小时改为服务结束后 **72 小时**（`completionWindowMs`），关联工单的处理期限仍为 24 小时。
- 窗口内既未确认也未异议、且满足以下全部条件时，系统自动确认并按订单金额**扣款一次**：服务足时且时间记录有效、按时开始、处理记录中没有顾客异议或服务方异常、支付授权有效（已 3DS、属于本单、额度足够）。完成记录为 `autoConfirmed: true`，时间线写入 `AUTO_CONFIRMED`，回执写明“72 小时无异议”。
- 任一条件不满足时仍为 `TIMED_OUT` 并开工单，不自动扣款。**只要出现过异议或异常**，即使店铺复核后重新请求确认，后续沉默也不会被视为验收。
- 顾客端的结算说明、订单说明和验收面板均三语告知 72 小时规则；验收面板在可自动确认时显示截止前提出问题的提示，其余状态显示“不自动扣款”。
- 即时单：技师到达后即可开始，不再等待预计开始时间；最早结束时间仍按实际开始 + 购买时长计算。指定时间预约仍不能早于预约时间开始。

## 正常履约

1. 技师完成任务确认、出发和到达后，服务端核对预约开始时间；提前开始返回 `SERVICE_TOO_EARLY`。
2. 实际开始时间由服务端记录。最早结束时间 = 实际开始时间 + 下单快照中的购买时长。晚开始必须顺延，不能按原预约结束时间提前结束。
3. 服务时长不足时返回 `SERVICE_TOO_SHORT`，不改变订单版本、不释放排班、不写入扣款和财务流水。界面同时提供异常入口。
4. 足时提交 `COMPLETE` 后，订单进入 `AWAITING_COMPLETION`。释放技师排班占用，隐藏技师可见的详细地址，支付仍未扣款，不能评价或按已完成收入结算。
5. 用户核对服务、时长和订单金额，勾选确认后提交。服务端再次核对本人身份、订单版本、结束时间、确认期限、金额和有效支付授权，原子地完成订单、扣款、平台费和财务流水。
6. 相同重试键不重复扣款；不同重试请求及并发操作受订单版本和状态约束。售后、退款、评价和复订从原订单继续。

安全签到提醒也按实际开始时间加购买时长计算，另加 15 分钟宽限，不会因晚开始而提前触发。

## 异常分支

| 情形                       | 处理结果                                            | 后续动作                                                            |
| -------------------------- | --------------------------------------------------- | ------------------------------------------------------------------- |
| 技师或店铺报告提前结束     | 固定当时结束时间，暂停扣款，生成关联工单            | 时长不足不能靠等待或复核恢复正常扣款；店铺可无费用关闭              |
| 用户在服务中申请中止       | 明示中止后固定记录服务时长、释放排班，暂停扣款      | 店铺和平台核实，按异常处理                                          |
| 足时结束后用户有异议       | 暂停扣款，保留结束记录及工单                        | 店铺说明复核结果后重新请求用户确认；店铺不能代确认                  |
| 用户 72 小时未确认也未异议 | 满足足时、无异议/异常、授权有效时自动确认并扣款一次 | 记录 `AUTO_CONFIRMED`；否则 `TIMED_OUT`，生成工单与预警，不自动扣款 |
| 异议或异常复核后再次超时   | `TIMED_OUT`，不按沉默验收                           | 店铺复核后再次请求确认或无费用关闭                                  |
| 支付授权过期或不可用       | `PAYMENT_REVIEW`，不写入收入                        | 用户可更新可用的演示支付授权，再单独确认；无法恢复则联系店铺处理    |
| 更新授权前已有异议或超时   | 保留原有复核要求                                    | 更新授权不会解除异议、绕过店铺复核或直接扣款                        |
| 旧订单缺失可信开始记录     | 标记时间异常，不能正常完成扣款                      | 可记录异常和无费用关闭，不伪造开始时间                              |

服务中和等待验收期间，用户与店铺均不能通过原取消接口绕过处理流程。无费用关闭释放未扣授权，不产生取消费；已扣订单继续使用原退款流程。

## 三端及平台联动

- 用户首页保留待验收订单；临近改派确认仍优先。订单页展示预约、实际开始、最早结束、提交结束和确认截止时间，提供金额确认及异议入口。
- 技师端显示服务剩余时间；服务未足时不能提交正常结束。等待用户确认的订单不再占据技师下一笔可履约任务的优先位置。
- 店铺把等待用户确认和需要店铺复核分开统计；可复核重发确认、查看原工单或无费用关闭。已中止的不足时长服务不显示正常复核扣款入口。
- 平台新增 `COMPLETION_REVIEW` 预警，联动原订单和处理工单。工单结案与订单结束分别核验，不以订单关闭自动代替仲裁结案。
- 正常履约的服务收入在用户确认并实际扣款后进入账单和经营报表；取消费、爽约核实费用和退款继续按各自流水口径记录。尚未核验的售后工单继续阻断服务款结算，不把授权额计作收入。
- 共享处理时间线保留提交、异议、复核、确认、超时、授权更新和无费用关闭记录。顾客异议正文不向技师披露；管理后台订单列表剔除处理正文，正文通过有权限的工单查看。

## 接口

`GET /v1/bookings/:id/completion` 返回订单版本、服务端当前时间、最早结束时间和验收记录。需要订单所属账号或有权限的平台账号。

`POST /v1/bookings/:id/completion` 使用 `Idempotency-Key`，请求为 `{ version, action, note?, expectedAmount? }`。不接收客户端提供的开始、结束、扣款或确认时间。

| action        | 身份               | 主要条件                                                              |
| ------------- | ------------------ | --------------------------------------------------------------------- |
| `CONFIRM`     | 所属用户           | 足时正常结束且等待确认，核对 `expectedAmount`，有效授权，未过确认期限 |
| `DISPUTE`     | 所属用户           | 服务中或等待验收；说明至少 10 个字符                                  |
| `EXCEPTION`   | 所属店铺、获派技师 | 服务中或等待验收；说明至少 10 个字符                                  |
| `REVIEW`      | 所属店铺           | 足时且时间记录有效；异议或超时状态；说明至少 10 个字符                |
| `VOID`        | 所属店铺           | 等待验收且未扣款；说明至少 10 个字符                                  |
| `REAUTHORIZE` | 所属用户           | 支付待核验；核对 `expectedAmount`；仅更新已有可用演示授权，不扣款     |

原 `POST /v1/staff/tasks/:id/events` 的 `START` 增加开始时间门禁，`COMPLETE` 只提交结束请求。

## 验收结果

- 542 项后端测试、65 项前端模型及会话测试通过，共 607 项；包含提前 1 毫秒、晚开始、缺失开始记录、并发确认、幂等、金额变化、跨账号、短时中止、超时和授权更新保留异议等分支。
- 17 组隔离 HTTP/SSR 检查，共 1514 项通过，其中新增履约验收 97 项。旧财务、退款、年费、发票和报表检查改为经过足时服务及用户确认后再记收入，跨日本日期的报表按实际扣款日期验证。
- 实际浏览器完成 14 项业务断言、36 组三端 × 三语言 × 四种宽度布局、6 组确认弹层检查；无横向溢出，主要操作按钮至少 48px，控制台无警告或错误。
- H5 实测“开始 → 提交结束 → 用户异议 → 店铺工单复核 → 用户确认 → 售后入口”；另实测提前中止 → 店铺无费用关闭，以及超时 → 平台预警 → 店铺复核 → PC 用户确认。
- 类型检查与生产构建通过。浏览器截图在 `docs/screenshots/completion/`，执行记录在 `.qa/completion-*`。

测试使用独立内存数据库与专用测试启动入口。受令牌保护的时钟仅存在于 `scripts/fixtures/api-test-server.mts`，主应用不导入、不提供该接口；没有将跳过时间门禁的开关加入业务 API。未通过测试写入常用预览数据库。

当前扣款、授权更新和通知仍为本地演示。服务端时间门禁不是到访或实际服务质量的外部证明；真实 PSP 授权/扣款回调、通知送达和线下证据核验仍需接入，现有生产禁用门禁保留。
