# 上门／到店由顾客主动选择

更新：2026-10-26。按用户最新要求实施，替代前一方案中的默认上门和单一方式自动选择。

## 展示与预约

- 首页、发现、项目列表、技师列表和详情页移除重复的顶部服务方式切换。保留现有配色、三入口、推荐数量和 H5/PC 布局。
- 浏览默认包含合格的两种供给，只有到店业务的店铺也能被看到。现有筛选可限定方式；筛选不是预约确认。
- 卡片价格分别标注“上门服务／到店服务”及相应金额、起价和时长。不会以到店低价作为上门报价。店铺安排价格和指名价格继续分别计算。
- 同店、同源且同时长的已生成价目合并展示，保留各方式的人员与价格。只有名称相同的不同项目不会合并。技师目录按人去重。
- 详情预约区与独立预约页共用主动选择逻辑。普通预约入口初始两项均未选中，选择前不请求可约时间，也不开放报价操作。
- 只有一种可售方式时也由顾客点击确认；另一项说明暂不提供，不自动代选。
- 选定后显示方式摘要与“更改”。从详情选好再进入独立预约页，或刷新本次预约，保留已选方式。
- 方式切换保留仍然支持的同源项目，重新校验价格、人员、语言和可约时间，清除旧时段。不自动替换不相关项目。
- 到店不再显示上门地区或“填写地址”的指引，展示门店和联系信息。结算、最终确认及订单持续显示已选方式。

## 数据与兼容

- 浏览使用现有 `fulfillmentMode=ALL`，仅对顾客展示层做合并。报价和成交仍使用独立价目与明确的服务方式。
- H5 技师接口扩展 `ALL`，每位技师新增可选字段 `modePrices`，包含各方式的起价与时长；原单方式接口保持兼容。
- 同一次预约通过 `modeConfirmed=1` 携带顾客主动选择。普通跨页面浏览参数不携带该确认；只有 `fulfillmentMode` 的旧链接仍需顾客选择。
- 确认标记只管理界面状态，不作为权限、价格或库存依据；服务端继续按当前能力与资源校验。
- 已成交订单的方式、地点和政策快照不变，支付能力不扩展。

## 本轮验证

- 新增顾客模型测试：旧链接不会自动确认、仅到店供给可见、两种价格独立、同源价目合并、同名项目不误合并、地区交集。
- 新增后端测试：混合目录按技师去重、分别报价、仅到店供给及翻页不重复。
- 在一次性内存数据库与独立预览服务验证真实浏览器交互，未修改本地演示库。
- 三语验证主动选择、方式切换、同源项目保留、正确费用与地点；验证详情选择进入预约不重复、方式切换清除旧时段、重新报价后进入到店结算、单一方式明确确认与刷新保留。
- 修复“尽快预约”偏好导致离线技师详情丢失原套餐的导航回归。详情静态菜单与即时可用性分别处理；预约仍重新校验实际可约时间。未选择服务方式时刷新也保留浏览中的项目和语言。
- 检查首页、项目、技师、店铺及技师详情在 320/390/768/1440 宽度下无横向溢出；技师目录三语同样检查价格是否越出卡片。
- 单元检查通过：后端 719 项、前端 130 项；最新生产构建与类型检查通过。H5 三语接口及 SSR 检查增加 12 项主动选择/导航断言，291 项全部通过。
- 修复导航回归后，最终完整 19 组流程全部通过，共 1,929 项接口/SSR 断言。此前热更新及并发构建期间出现过页面 500；构建结束后独立复测及最终整轮均通过。
- 最终完整流程结果见 `.qa/mode-choice-flows-final.log`，构建见 `.qa/mode-choice-final-build.log`；真实支付及目标 PostgreSQL 部署验收不包含在本轮。

开始使用到店仍需店铺提交资料并通过平台审核。测试使用的临时门店未写入现有演示库。
