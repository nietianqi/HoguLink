# 技师端业务与体验完善方案

## 产品边界

店铺受理与安排技师，技师确认本人任务并履约，顾客验收，店铺负责技师结算。平台不把订单金额展示为个人工资，不增加抢单大厅或提现。保持现有绿色视觉和四个手机主入口，日英中业务规则一致。

两份评估中已有能力予以保留：独立任务详情、可见时自动刷新、超时安全签到、店铺/平台安全队列、邮件通知适配器、照片视频双重审核。改进入口、时效、文案和状态反馈，避免重复建流程。

## 本轮实施

1. 到店消息按任务权限开放，不依赖顾客上门地址；上门/到店的地点、准备说明、日程、快捷消息分别展示。
2. 新任务提醒可由技师启用，包含声音、支持设备的震动、浏览器通知与标题数量。清楚说明网页提醒的使用范围；回到前台/恢复网络立即同步，不把未成功提交的操作显示成已完成。
3. 指定时间上门的出发、到达记录最早在预约前90分钟开放，前后端使用同一规则；即时单不套用指定时间限制，到店不显示出发/到达。开始和结束仍执行原有服务时间及状态校验。
4. 新增深夜安全限制在等待店铺确认期间也对新预约和新分派临时生效，已有任务不自动取消；解除由技师主动操作。店铺拒绝后明确提示结果。
5. 当前任务展示真实下一步和相对日期，手机固定主操作与求助入口。结束服务继续走原有足时及异常处理，不能从固定按钮绕过服务校验。
6. SOS 后接入现有紧急帮助与主动一次性位置分享。显示事件记录、通知投递及店铺/平台跟进状态，入库或发信成功均不代表救援已到达；保留拨打紧急服务的明确入口。
7. 我的资料拆为公开资料、照片视频、服务设置、业绩与评价。个人业绩统计本月完成单数和已购服务时长，评价使用已有本人审核通过的匿名接口。不虚构收入、好评率或距离。
8. 精简重复快捷入口、顾客站页脚、装饰英文、重复免责声明；客服和质量页面沿用技师导航与语言切换。修正休息申请空状态。

## 验收重点

- 到店任务可读写订单消息；拒绝、撤回、待顾客同意、已结束及其他技师任务仍不能越权。
- 90分钟边界的前后端行为一致，不能提前写履约时间；晚到、即时单及到店流程正常。
- 待审批安全条件阻止新的深夜首客预约，但不更改已有订单；店铺、技师权限隔离。
- 主操作不重复提交、不绕过足时和核销；断网/过期版本保留用户输入并给出明确恢复操作。
- SOS 不自动申请定位权限，不向顾客泄露安全反馈或内部处理备注。
- 提醒按任务和截止窗口去重，首次启用可提醒已有待办；拒绝浏览器权限后网页功能仍可使用。
- 三语及390px手机、PC布局实测；使用独立数据库，不写主预览数据。

## 另行接入的能力

Web Push/锁屏推送需订阅、VAPID配置和设备送达验收；LINE、短信、隐私号需服务商账号。延长服务涉及价格、排班、顾客授权及补款，随支付阶段单独实施。个人分成需店铺明确配置并确认后才能展示。简介修改需完整内容审核链，不能绕过店铺/平台审核直接公开。履约事件不做离线自动补写，以免延迟上报制造错误服务时间；本轮提供断网提示和恢复重试。

- 后端784项测试、前端154项模型测试通过；技师HTTP冒烟75项检查通过。
- 类型检查和生产构建通过，工作区差异无空白错误。
- 独立内存数据库中实际确认获派任务、发送到店订单消息、记录SOS、申请安全条件；页面核对了未来任务的出发时间窗、服务结束按钮足时限制、匿名评价与月度统计。
- 以390px手机和1440px PC检查工作台及任务页面；查看中文、英语日程、日语业绩页面及语言切换。用户发布的评价原文保留原语言。
- 浏览器发现并修复快捷消息挤占输入框、求助文字竖排、禁用按钮背景透字，以及标题角标与路由元数据互相触发的问题。最终用定时更新标题，并重新验证带待办数量时的连续切换。
- 通知排队、失败、部分受理、已受理和仅账号邮件范围在后端测试中验证，技师视图不含收件人或内部处理备注。
- 未授予真实定位或系统通知权限，没有发送外部邮件/短信、拨号或实付。锁屏推送、设备震动和真实投递仍需配置后的真机验收。
- 测试数据位于独立环境，不写主预览；主前后端健康检查均为200。
