## 3. 五条原则

每次改页面前先对照这五条。

- **一屏一件事**：每页只有一个主行动。首页是「开始预约」，详情页是「选择时间」，下单页是「确认」。
- **三秒看懂**：卡片只放做决定需要的信息：谁、多少钱（含什么费用）、最早什么时候能来。其余放进详情。
- **克制**：五档字号，最小 12px。一个品牌深绿、一个价格红，其余都是中性色。每张卡片最多 2 个标签。
- **留白代替线框**：少用边框和底色块，靠间距和字重区分层级。「大气」主要来自这里。
- **H5 与 PC 同构**：同样的结构、同样的组件。PC 只是网格更宽、一行放更多，不另做一套内容。

## 4. 信息架构

顾客的主线：找人或找店 → 选时间 → 下单 → 看订单 → 消息和售后。导航保持五个，重新分工。

| 导航 | 负责                                                                                | 移出                               |
| ---- | ----------------------------------------------------------------------------------- | ---------------------------------- |
| 首页 | 开始预约，加精选：限时优惠、同城店铺、推荐技师                                      | 完整目录、招商、浏览记录、收藏入口 |
| 发现 | 内容：预约指南、安心服务、店铺动态                                                  | 店铺列表（并入预约）               |
| 预约 | 唯一的选购入口：「技师｜店铺｜项目」切换 + 一条筛选栏（地区、时长、语言、预约方式） | —                                  |
| 消息 | 订单消息、活动消息                                                                  | —                                  |
| 我的 | 订单、收藏、浏览记录、设置，以及「商户入驻」入口                                    | —                                  |

项目去重：按项目名合并，例如「舒缓放松 · 60 / 90 / 120 分钟 · 3 家店提供 · ¥8,200 起」，点进去再选店或选人。

## 6. 卡片与页面模板

卡片规范影响面最大，先定下来，所有列表共用。

- **技师卡三组信息**：姓名和认证 / 评分 · 近 90 天单数 · 所属店铺 / 价格（写明含什么）+ 最早可约 + 一个按钮。语言和标签放进详情或筛选。
  - 示例：`葵 [已核验]` / `暂无评价 · 近 90 天 5 单 · 凪 · 东京` / `¥8,700 / 60 分钟 · 今天 20:00 起可约 · [预约]`（价格含指名费与交通费）
  - 三组信息指语义层级，不强行限制三条视觉行。中、日、英文长文本允许换行，保留最小 12px 字号。
- **店铺卡**：店标、店名、一行事实（地区、技师人数、受理方式）、起价、「进店」。
- **项目卡**：项目名、可选时长、几家店提供、起价。同名项目只出现一次。
- **标签**：每张卡最多 2 个，优先级：限时优惠 > 可即时上门 > 免交通费。
- **详情页（技师 / 店铺共用）**：身份与数据 → 价目 → 评价 → 须知 → 底部固定栏（价格 + 「选择时间」）。法律与经营信息默认折叠，标题保留「特定商取引法に基づく表記」。
- **下单三步**：
  1. 选时间：日期、时段；价格摘要固定在底部。
  2. 地址与确认：常用地址一键选；酒店需房号与许可；确认冻结报价、取消费率和服务条款。
  3. 提交结果：提交预约后进入订单，明确店铺受理、技师确认、顾客验收各阶段。

  保留现有三页流程和模拟支付入口。本轮不重写报价、授权或合同成立时点。取消政策默认展示所有取消费率及边界，较长的爽约认定过程收进可展开全文。

## 10. 不变的底线

本轮只改展示和结构，以下业务规则一律不动。

- 只显示真实数据：评分、单数、收藏来自已审核评价、已完成订单和真实收藏；没有就写「暂无评价」。
- 不做「新人」「人气」「颜值」类标签，不按外貌或人气排序。
- 划线原价按二重価格表示规则：原价满 28 天，且近 56 天优惠天数不超过一半才显示。
- 定位只在设备上计算，服务器只收到区名。
- 价格写清是否含交通费、指名费；报价、扣款、取消规则不在本轮改动范围。
- 不复制参考站的图片、文案、数据或品牌。

## 12. 本轮落地与验收（2026-10-20）

### 已落地

- **首页减法**：H5 与 PC 使用同一个首页组件。保留快速预约、真实限时优惠、店铺与技师精选；删除完整目录、重复快捷入口及招商横幅。H5 预览 3 家店铺（横向浏览）及 3 位技师，PC 展示 3 家店及 6 位技师。地区、时长在快速预约中选择，预约方式改为清晰的双选按钮。
- **当前订单优先**：已登录顾客有进行中的预约时，首页显示真实状态和订单入口；改派同意、服务完成确认明确提示。读取失败显示重试入口，不伪造空订单。
- **统一预约入口**：`/therapists?view=therapists|shops|services` 共用地区、时长、语言及预约方式筛选。搜索、排序、交通费与优惠作为更多筛选。具体日期、时段在下单时选择；目录的“指定时间”表示预约方式，不表示已核验顾客尚未选择的日期。无结果与接口失败分开处理。
- **兼容旧入口**：`/services` 转入预约项目页，保留有效项目、优惠及筛选参数；`/discover?tab=shops` 转入预约店铺页。发现中的店铺动态使用 `tab=stories`，后端仍使用原内容分类，文章回退与搜索保持一致。
- **项目合并**：同名项目按三语名称聚合，展示真实店铺数、可选时长及最低店铺安排价，再选择具体店铺、时长与指名方式。起价绑定实际菜单，不把较低的长时项目价格标成 60 分钟；“提供”不等同于已经核验某时段可约。
- **价格与流程**：指名总价和店铺安排价分别说明。优惠保留有效原价比较及截止时间；进入项目选择后重新核对供给、价格和即时可约状态。店铺进入下单及返回目录时保留地区、语言、即时预约意图。
- **详情、下单、我的**：菜单优先于次要店铺介绍；法律经营信息标题保留且可展开；取消费率保持可见，爽约认定过程可展开。保留服务／时间、地址与报价确认、提交结果三步及顾客验收规则。“我的”共用资料与工具组件，优先显示当前订单；未开放的优惠券、储值只保留次要说明入口。
- **数据修复**：技师统计读取失败保持“未知＋重试”，不再显示为零；修复预约标签切换时组件键重复的问题。
- **样式清理**：新增 10 个基础组件；移除旧首页、旧目录与重复账户视图。删除不用的目录样式文件，合并共用价格、店铺样式为 `catalog.css`，清理失效选择器。未新增 `!important`。

### 验收口径

- 首页面积以 `main` 主内容为准；固定导航、顶栏、折叠帮助区及浏览器安全区单列。默认中文、60 分钟、无进行中预约；真实优惠和当前订单会改变高度。
- 文案完整优先于挤压行数。英文、日本語较长时允许卡片增高；320px 保持可读与无横向溢出，不以裁掉费用、状态或政策换取高度。
- “CSS 颜色值数量”统计整个项目，包含未改版的工作台和历史回退色；顾客端实际渲染的颜色与全项目源码色值分别记录。
- 截图与机器测量存放在本地 `.qa/ui-simplification-20261020/`；该目录不进入 Git。
